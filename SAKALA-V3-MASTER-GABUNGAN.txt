A.1 TAGLINE INTERNAL
--------------------------------------------------------------------------------
    FULL POWER, LOW FRICTION

  Sub-prinsip     : DON'T REMOVE COMPLEXITY. ABSORB IT.
  Operasional     : ONE INTENT -> ONE ACTION -> ONE RESULT
  Data            : ONE INPUT -> MANY MODULES
  Penjadwalan     : OPERATOR MENENTUKAN BATAS DAN ARAH.
                    SISTEM MENENTUKAN SUSUNAN TERBAIK.
  Keselamatan     : NO SILENT DAMAGE.
  Optimasi        : PRESERVE FIRST, OPTIMIZE SECOND.
  Arsitektur      : POWERFUL INSIDE, SIMPLE OUTSIDE.
  Identitas       : THE HERITAGE IS DISCOVERED, NOT DISPLAYED.
  Kemewahan       : LUXURY IS NOT ADDED. LUXURY IS ENGINEERED.

--------------------------------------------------------------------------------

BAGIAN C — SCHEDULE ENGINE (Otak Sistem)
================================================================================

C.1 MASTER EQUATION
--------------------------------------------------------------------------------
  USER INTENT + MINIMUM DATA + SCHOOL TIME STRUCTURE + HARD RULES
  + SOFT PREFERENCES + EXISTING SCHEDULE + LOCK + PROTECTED CONTEXT
        v
  SCHEDULING ENGINE
        v
  VALID + PRESERVED + OPTIMIZED + EXPLAINABLE
        v
  PREVIEW -> SAFE APPLY -> VERSION + HISTORY

C.2 HIERARKI PRIORITAS (tidak boleh dibalik)
--------------------------------------------------------------------------------
  LEVEL 0  VALIDITY     (jadwal harus valid)
  LEVEL 1  PRESERVATION (pertahankan yang sudah ada)
  LEVEL 2  QUALITY      (distribusi, gap, beban, konsistensi)
  LEVEL 3  PREFERENCE   (waktu, prioritas, pemetaan, persebaran)

  Ringkas: VALID FIRST. PRESERVE SECOND. OPTIMIZE THIRD. EXPLAIN ALWAYS.

C.3 HARD CONSTRAINT (tidak boleh dilanggar)
--------------------------------------------------------------------------------
   1. Teacher clash — guru tidak bisa 2 kelas di slot sama
   2. Class clash — kelas tidak bisa 2 pelajaran bersamaan
   3. Room clash (jika room scheduling aktif)
   4. Non-teaching slot (Istirahat/Kegiatan/Non-Aktif) bukan slot mengajar
   5. Target JP harus dipenuhi sejauh feasible
   6. Session structure valid
   7. LOCK tidak boleh dipindahkan
   8. Protected context tidak boleh diubah
   9. Hard availability
  10. MAKSIMAL 3 JP BELAJAR BERTURUT-TURUT per hari (guru DAN kelas)
  11. Official max JP/day bila mandatory
  12. Room capacity/type bila mandatory

C.4 CONTINUITY RULE (LOCKED — koreksi penting)
--------------------------------------------------------------------------------
  Learning continuity TIDAK diputus oleh ISTIRAHAT / KEGIATAN / NON-AKTIF.

  Contoh KONTINU (2 JP):        Contoh TIDAK kontinu (1 + 1):
    P4 IPA                        P4 IPA
    P5 ISTIRAHAT                  P5 IPS      <- learning session lain
    P6 IPA                        P6 IPA

  Yang dihitung untuk aturan max-3 adalah LEARNING JP, bukan nomor periode.
  Internal: counts_as_learning = true/false. Operator hanya lihat
  "jam pelajaran berurutan".

C.5 SOFT CONSTRAINT (boleh dikompromikan)
--------------------------------------------------------------------------------
  Preferensi guru, waktu preferensi mapel, pola distribusi, jumlah
  pertemuan, prioritas pemetaan, soft availability, preferensi pagi.

  URUTAN RELAKSASI kalau tidak dapat hasil ideal:
    1. Time preference  2. Distribution preference  3. Gap preference
    4. Daily balance    5. Soft preference lainnya
  TIDAK BOLEH direlaksasi otomatis: teacher/class/room clash, LOCK,
  protected context, seluruh HARD constraint.

C.6 GENERATOR UX (LOCKED)
--------------------------------------------------------------------------------
  AREA -> CARA KERJA -> PROFIL JADWAL -> BUAT JADWAL

  AREA        : Semua Kelas / Satu Kelas / Beberapa Kelas / Bagian Tertentu
  CARA KERJA  : Otomatis / Susun Ulang / Isi Slot Kosong
  PROFIL      : Otomatis / Seimbang / Utamakan Pagi / Lebih Merata / Custom

  Area yang dipilih = ACTIVE AREA (boleh diubah engine)
  Di luar area     = PROTECTED CONTEXT (tidak diubah, TAPI tetap jadi constraint)

C.7 ALUR PENUH GENERATOR
--------------------------------------------------------------------------------
  BERANDA -> JADWAL -> BUAT/PERBAIKI JADWAL -> AREA -> CARA KERJA -> PROFIL
  -> BUAT JADWAL -> ENGINE -> VALIDASI -> 3 VARIASI -> PREVIEW -> PILIH
  -> TERAPKAN -> JADWAL AKTIF

C.8 FEASIBILITY (3 status)
--------------------------------------------------------------------------------
  FEASIBLE                  Jadwal dapat dibuat
  FEASIBLE WITH TRADE-OFF   Bisa, tapi sebagian preferensi tak terpenuhi
  INFEASIBLE                Tidak ada solusi valid dengan kondisi sekarang

C.9 TIGA VARIAN (bahasa manusia, BUKAN skor)
--------------------------------------------------------------------------------
  01  PALING SEIMBANG      -> prioritas distribusi keseluruhan
  02  LEBIH SESUAI WAKTU   -> prioritas preferensi waktu
  03  LEBIH MERATA         -> prioritas penyebaran beban

  DILARANG menampilkan: "Score 94.82", "solver confidence 0.984",
  constraint ID, terminologi solver.

C.10 HUMAN-READABLE ERROR (wajib)
--------------------------------------------------------------------------------
  JANGAN : "Constraint violation: UNSAT."
  PAKAI  : "Jadwal belum dapat dibuat karena beban mengajar Pak Ahmad
            membutuhkan 30 JP, sementara slot yang tersedia hanya 20 JP."
  Lalu   : [Lihat Beban] [Coba Cara Lain] [Ubah Struktur Waktu]

  Struktur wajib: MASALAH -> PENYEBAB -> DAMPAK -> SOLUSI -> AKSI

C.11 STATE SLOT & GOVERNANCE
--------------------------------------------------------------------------------
  Status entry : EMPTY / SCHEDULED / AUTO / MANUAL / LOCKED / CONFLICT /
                 WARNING / PREVIEW / PROTECTED

  MANUAL != LOCK  (penting!)
    AUTO    Engine membuatnya, boleh diubah
    MANUAL  Operator pernah mengatur, TIDAK otomatis terkunci
    LOCK    Dilindungi, engine WAJIB menghormati, tidak boleh auto-unlock

C.12 20 HUKUM SCHEDULING WORKSPACE
--------------------------------------------------------------------------------
  01 The workspace shows the truth
  02 The grid is a canvas, not a spreadsheet
  03 One schedule, multiple perspectives
  04 Academic context always precedes schedule action
  05 Validity before quality
  06 Quality before preference
  07 Manual != Lock
  08 Lock means protected
  09 Drag does not bypass validation
  10 No silent reschedule
  11 No silent replacement
  12 No unrelated disruption
  13 Impact matches action risk
  14 Preview before meaningful change
  15 Active, preview and history must never be confused
  16 Context never gets lost
  17 Information > Illustration
  18 Meaning > Decoration
  19 Luxury through continuity, not ornament
  20 The schedule should feel complex to the engine and simple to the operator

D.9 SMARTSELECT (LOCKED)
--------------------------------------------------------------------------------
  Aturan tampil:
    <= 3 pilihan  -> tampilkan langsung (tanpa search)
    >  3 pilihan  -> search aktif
    ~200 pilihan  -> search sebagai default

  Ranking: EXACT -> PREFIX -> MULTI-TOKEN -> PARTIAL -> ALIAS/CODE

  Normalisasi contoh: "abd rah" -> Muhammad Abdul Rahman,
  "b indo" -> Bahasa Indonesia, "7a" -> VII A, "lab kom" -> Lab Komputer

  Empty: "Tidak menemukan 'Ahmadn'. Mungkin maksud Anda 'Ahmad'?"

KONSEP YANG SENGAJA MASIH TERBUKA (dari dokumen desain asli):
  - Detail algoritma solver
  - Mekanisme authentication
  - Mekanisme teacher read-only access
  - Detail substitution (guru pengganti)
  - Detail room scheduling
  - Detail curriculum rules
  - Detail combined class / group
  - Detail scoring internal & objective function
  - Detail permission system

  Hal-hal ini TIDAK BOLEH mengubah keputusan LOCKED di Bagian A.

ATURAN PERUBAHAN KE DEPAN:
  LOCKED     Tidak boleh diubah diam-diam
  EXTENSION  Boleh ditambahkan kalau kompatibel
  REVISION   Harus dibahas sebagai perubahan terhadap keputusan sebelumnya
  REMOVED    Tidak boleh muncul kembali kecuali pemilik produk secara
             eksplisit menghidupkannya
  INTERNAL   Boleh kompleks di engine, tapi tidak otomatis jadi UI operator

  Ide baru wajib diuji terhadap 7 pertanyaan:
   1. Apakah meningkatkan kemampuan?
   2. Apakah mengurangi beban operator?
   3. Apakah menjaga determinisme?
   4. Apakah menjaga data integrity?
   5. Apakah menjaga backward compatibility?
   6. Apakah tidak merusak keputusan LOCKED?
   7. Apakah benar-benar menyelesaikan masalah?

  Kalau tidak memenuhi, ide tersebut tidak boleh menggeser arsitektur utama.
